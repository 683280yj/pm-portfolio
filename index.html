CASE-001 / 多 AGENT 系统 SHIPPED · 运行中

「六部制」个人 AI 助理系统 / OpenClaw

产品定义 · 架构设计 · 成本工程 · 运维 — 独立负责

  • 问题：个人任务散落在聊天窗口里，单模型单线程作业——贵、慢、不可控，也没有分工与审核。
  • 方案：参照唐代三省六部制设计 10+ 常驻 Agent：三省决策（中书规划 → 门下审核 → 尚书调度），六部执行（吏·人事 / 户·财务 / 礼·文案 / 兵·安全 / 刑·合规 / 工·工程），另设太子（陪学）与早报（简报）。
  • 成本设计：按任务价值做 3 级模型分层——旗舰模型只留给决策链路，文案与高频工程任务由轻量模型承接。
  • 可靠性：主 → 备 → 应急三级模型 fallback，单点故障不影响在线；部署于云服务器，systemd 常驻。

设计原则 PRINCIPLES

① 决策与执行分离

规划必须过门下省审核再交尚书省调度——避免同一个模型既当运动员又当裁判，输出质量有把关链路。

② 成本跟着价值走

旗舰模型只花在决策与重推理链路；文案、高频工程任务由轻量模型承接。分层不是省钱技巧，是产品定价思维。

③ 任何单点都可降级

模型配置了三级 fallback：主供应商故障自动切备用，再切应急通道。可用性优先于单次回答质量。

04

路径

THE PATH

从计量经济学到 AI 产品经理——每一步都在解决同一个问题：让机器替人做重复的事。

起点 · 计量经济学

先学会向数据提问

经济学训练给了两样东西：用数据验证直觉的习惯，和「任何结论都有前提条件」的边界感。论文用 CFPS 数据研究土地集中政策对农村家庭消费结构的影响。

转折 · 把研究流程交给机器

把 stata-mcp 定制进论文工作流

数据清洗、跑回归、调稳健性检验——大量机械重复。发现开源项目 stata-mcp 后把它深度定制成自己论文流水线的执行引擎，AI 可以直接驱动 Stata 完成整个实证流程。第一次体会到：定义好接口，机器就能接管流程。

深入 · 运营一套多 Agent 系统

从工具到系统：六部制上线

单个工具不够了。设计并上线 10+ Agent 的个人 AI 系统，开始真正关心分工边界、成本预算、可靠性降级——这些全是产品问题，不只是技术问题。

现在 · AI 产品经理

把闭环变成职业

「用户要什么 → 系统怎么建 → 成本怎么算 → 坏了怎么办」——这个完整闭环是我已经在做的事，现在把它作为职业方向，到更大的场景里做一遍。
